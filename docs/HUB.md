# Оболочка JOI — сайдбар и хабы

Контракт навигации десктоп-приложения. Продуктовые ветки (сессия, Ember-пак, nhentai) живут в своих документах; здесь только **как попасть** и **куда не плодить второй пункт меню**.

Визуальный образец шапки с вкладками — раздел **Контент** (кикер источника + пилюли). **Прогресс** и **Мини-игры** повторяют ту же схему через `HubChrome`.

## Сайдбар

Один пункт = один хаб или один экран. Порядок сверху вниз:

| Пункт | NavId при клике | Что внутри |
| --- | --- | --- |
| Рулетка | `roulette` | Колёса, блок «Сегодня» |
| Сессия | `session` | Живой зал |
| Чат | `chat` | Свободный чат, Soul Memory |
| Магазин | `shop` | Угольки |
| Контракты | `contracts` | Доски на сегодня |
| **Прогресс** | последняя вкладка хаба (`diary` по умолчанию) | Дневник / Статистика / Достижения |
| **Контент** | `doujin` | nhentai + Gelbooru |
| **Мини-игры** | последняя вкладка хаба (`minigames` по умолчанию) | Игры / Аномалия / Ember Editor |
| Настройки | `settings` | Слоты, медиа, ИИ, голос |

Внизу: полный экран, свернуть панель. Это не маршруты.

Не возвращать в сайдбар отдельные пункты «Дневник», «Статистика», «Достижения», «Избранное», «Додзинси», «Аномалия», «Ember Editor».

## Хабы

Лист `NavId` не схлопывается: вкладка = тот же id, что раньше был пунктом меню. `App.tsx` по-прежнему монтирует страницу по `nav`.

### Прогресс

Кикер «Сессии», заголовок «Прогресс». Вкладки:

| Вкладка | NavId |
| --- | --- |
| Дневник | `diary` |
| Статистика | `stats` |
| Достижения | `achievements` |

`contract_journal` подсвечивает **Статистику** (журнал контрактов справа от графиков, не отдельная вкладка).

Повторный клик по «Прогресс» открывает последнюю вкладку (`localStorage` `joi-hub-progress-v1`).

Шапка вкладок **одного размера** на всех трёх экранах: колодец не сжимают соседние контролы (период статистики — под шапкой). Скролл только у тела страницы, не у всей `.page`, иначе полоса прокрутки прыгает шириной.

Код: `src/lib/hubNav.ts`, `src/components/HubChrome.tsx` (`ProgressHubChrome`), `src/components/hubChrome.css`.

### Контент

Кикер в шапке переключает **nhentai / Gelbooru**; вкладки общие: Новинки, Рекомендации, Поиск, Избранное, Списки. Состояние: `src/lib/contentHub.ts` (`joi-content-hub-v1`).

Сайдбар подсвечен при `doujin` и при старом `favorites` (глубокая ссылка на полку Gelbooru). Клик по пункту всегда ведёт в `doujin`.

Ветки: [DOUJIN.md](DOUJIN.md) (nhentai, ридер, прогон). Gelbooru — та же оболочка, локальная полка `mediaFavorites` кормит сессию и магазин. Несохранённое видео в плеере идёт через `/api/media-proxy` с параллельными Range; сохранённое играет локальным blob. Превью в Electron — с CDN.

### Мини-игры

Кикер «Угольки», заголовок «Мини-игры». Вкладки:

| Вкладка | NavId |
| --- | --- |
| Игры | `minigames` |
| Аномалия | `ember` |
| Ember Editor | `ember_editor` |

Повторный клик по «Мини-игры» открывает последнюю вкладку (`joi-hub-play-v1`).

На каталоге игр шапка обычная; в Аномалии и редакторе — `tight`, поверх своих тулбаров. Пока запущена конкретная мини-игра (пазл, раннер, …), шапка хаба скрыта — выход в каталог возвращает вкладки.

Play для человека в JOI: **Мини-игры → Аномалия** → стадия → Начать. Редактор: **Мини-игры → Ember Editor**. Это **frozen Three-shell**: новый play и authoring карт — Godot (`ember-godot`). Headless CLI/MCP не ходят через сайдбар — см. [EMBER_AI_HANDOFF.md](EMBER_AI_HANDOFF.md) §2.1.

## First-visit briefing

Подсказки разделов (`src/lib/sectionBriefings.ts`) завязаны на хаб, не на каждую вкладку:

- любая вкладка Прогресса → briefing `diary`;
- `favorites` → briefing `doujin`;
- Ember play/editor и каталог мини-игр — без overlay.

`briefingNavFor(nav)` — единственная точка маппинга. Не добавлять отдельные тексты для `stats` / `achievements`.

## Как менять

1. Новый **экран сессии / магазина / настроек** — новый пункт сайдбара, только если это не вкладка существующего хаба.
2. Новая **вкладка хаба** — id в `hubNav.ts` (или `contentHub.ts`), chrome, `App.tsx`, тесты, эта страница.
3. Не копировать пилюли вкладок в `styles.css`: Прогресс/Мини-игры — `hubChrome.css`; Контент — `doujin.css`.
4. Не вводить `NavId` `"progress"` / `"play"` / `"content"`: сайдбар резолвит хаб в существующий лист id.
