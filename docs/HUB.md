# Оболочка JOI — сайдбар и хабы

Контракт навигации десктоп-приложения. Продуктовые ветки (сессия, nhentai и остальные источники Контента) живут в своих документах; здесь только **как попасть** и **куда не плодить второй пункт меню**.

Рабочий размер окна — Full HD (**1920×1080**): так стартуют Electron и fallback-браузер (`scripts/launch-window.mjs`). Если монитор меньше — окно занимает рабочую область, не вылезает за панель задач. Агент при проверке UI ставит вкладку на 1920×1080; узкая панель Cursor — не эталон вёрстки. Под узкие экраны оболочка пока не адаптируется.

Визуальный образец шапки с вкладками — раздел **Контент** (кикер источника + пилюли). **Прогресс** и **Мини-игры** повторяют ту же схему через `HubChrome`.

## Сайдбар

Один пункт = один хаб или один экран. Порядок сверху вниз:

| Пункт | NavId при клике | Что внутри |
| --- | --- | --- |
| Рулетка | `roulette` | Главный экран: узкая команда «Пусть решает», пульт План/Медиа/Игрушки/Квесты занимает середину, лента «Сегодня» снизу. Вкладка «Квесты» — пул заданий сессии (можно выключить тип). Колёса — с выбранной доски Контента. Медиа: откуда → накал → список или поиск. |
| Сессия | `session` | Живой зал. В слоте **Песочница** на этом экране вкладка **Лаборатория** (рядом с очередью): собрать блоки, взять готовые из плана рулетки, вызвать выбранное задание, сверху панели — тоглы **эффектов** (гипноз / манты / плашка 修正 или лента) для проверки на кадре. Во время прогона «В очередь» / «Добавить» дописывают в конец, не перезапускают сессию. После успешного старта черновик очереди очищается. Не пишет дневник и не открывает окно завершения. Тулбар: **цензор** закрывает кадр (мозаика / плашки на фото; видео и гифки целиком блюр без нейросети); в Настройках можно включить слежение нейросетью на фото (аниме тело + соски + руки + позы, YOLOX; один прогон на кадр). У Искорки поверх сессии — **эффекты** (спираль, артефакты, манты; Настройки → Геймплей → Эффекты). Госпожа может включить цензор из чата и запретить снимать до конца сессии. |
| Чат | `chat` | Свободный чат, Soul Memory. После сессии Conductor кладёт короткую сводку в те же world events — чат помнит исход, не тащит лог и не делает отчёт на «Привет». Предпочтения и жёсткие границы — компактный stance в памяти этой госпожи, не отдельный экран. Карточка под репликой появляется только из валидированного JSON роли **Разбор** (клетка/пробка, denial, сессия, задание из каталога, check-in); текст реплики и regex карточки не создают. Принять нужно явно. «Согласен» на сессию сразу собирает её существующим Conductor и запускает без второй карточки. По умолчанию сборка программная; опциональная роль **Планер** вызывается только после принятия, выбирает только существующие функции/паттерны, а при невалидном результате срабатывает программный fallback. В настройках модели чата (шестерёнка → Модель) и в Настройки → ИИ ресурсы: список скачанных Ollama-моделей, роли Чат / Роутер / Разбор / Планер, стиль ответа. Router одним JSON-патчем обновляет структурную память и, если режим памяти разрешает, темы и дневник. Шестерёнка → Память: очистить её дневник или темы, переписка отдельно. В разработке (и по галке «Контекст хода») под репликой сворачивается, **почему** модель получила такой промпт — копируется текстом, в Soul save не пишется; там же виден lifecycle карточки от `created` до `accepted` / `refused` / `blocked` и `started` / `failed`. `npm run soul-eval` сохраняет raw speech/prompt и измеряет mode/subjects/sections, размер промпта, повторы, вопросы в конце, retry/JSON-validity/latency ролей, false-positive карточки и Planner fallback reasons; `--router-acceptance` отдельно гоняет живые no-op / habit / hard-boundary / topic+diary кейсы. |
| Магазин | `shop` | Угольки |
| Контракты | `contracts` | Доска дня (пять случайных карточек) и долгие серии: тематические пресеты на 7 или 30 последовательных локальных дней, с нарастанием. Журнал итогов — не здесь, а в **Прогресс → Статистика**. Не внешние рулетки. В слоте **Песочница** вкладка **Редактор**: одиночные карточки и **Пресеты серий**. | **Прогресс** | последняя вкладка хаба (`diary` по умолчанию) | Дневник / Статистика / Достижения |
| **Контент** | `doujin` | nhentai + booru (Gelbooru / censored / blacked / realbooru / xbooru / hypnohub) + joidb |
| **Мини-игры** | последняя вкладка хаба (`minigames` по умолчанию) | Игры (пазл, память, раннер, дудл, ферма). Вкладки Аномалия / Ember Editor — локальный замороженный эксперимент, не развиваем |
| Настройки | `settings` | Слоты, медиа, ИИ, голос. Геймплей: рулетка, теги, CBT, **цензор** кадра сессии (зоны грудь/пах/член/зад/живот/подмышки/стопы/руки/лицо; член выкл — дырка в мозаике паха), **эффекты** Искорки (гипноз / надписи, список фраз), игрушка. После этого окно спрашивает про **Ollama и модель чата** — выбранное качается по очереди, можно пропустить и скачать позже в «ИИ ресурсы». Повторный запуск не качает заново и не поднимает WD14, если файлы уже на диске. |

Внизу: полный экран, свернуть панель. Это не маршруты.

В «ИИ ресурсах» текстовые Ollama-модели/роли и голосовые веса разделены внутренними вкладками. В «Голосе» Qwen показывается одним движком, а выбор **Быстро · VRAM** / **Экономно · RAM** находится внутри него; адрес сервера, model id и API key спрятаны в «Сервер и модель». Проба Qwen показывает фактическое время синтеза, длину аудио и скорость относительно realtime. Оформление этого домена принадлежит `src/components/voiceSettings.css`, не legacy `styles.css`.

Groq подключается через **Чат → настройки → Модель**. Вкладка **Groq** — только облачный разговор: ключ, без запуска Ollama, без локального запаса, без служебных ролей (память / разбор / планер). Вкладка **Groq + Ollama** — связка: по умолчанию приватный режим; возле ввода явный переключатель «Приватно · Ollama» / «Обычный разговор · Groq». Для облака нужен пользовательский ключ, кнопка «Проверить Groq» отправляет только тестовое приветствие. Локальная модель сохраняется при переходе с Ollama; ключ Groq не стирается при переключении вкладок Ollama ↔ Groq / Groq + Ollama. Ключи Groq, OpenRouter и OpenAI хранятся отдельно: смена вкладки не затирает чужой ключ. Модель чата тоже помнится по вкладке; адрес и необязательный ключ вкладки **Свой** (LM Studio) переживают переключение. Groq и Groq + Ollama делят один ключ Groq и одну облачную модель. В Настройки → ИИ ресурсы кнопка **чат** назначает локальную Ollama, не переключая облачный режим. Служебные роли в связке всегда локальные. При 429/5xx/сетевом сбое/таймауте связка переключается на доступную Ollama с сообщением о фактическом источнике ответа; Retry-After выдерживается между ходами. Чистый Groq в этом случае показывает ошибку, а не локальный ответ. Ошибки ключа и модели показываются явно. Это ручной выбор приватности, не автоматический детектор интимного контента: всё написанное в облачном режиме передаётся Groq.

В composer переключатель Ollama / Groq компактный, под полем ввода рядом с «Голос». Полные пояснения приватности доступны в настройках и подсказках кнопок. Успешные ответы не создают карточки «Команда»; переход на локальный резерв показывается единственным статусом под панелью ввода, который очищается на следующем запросе или смене режима.

Во время ответа или перегенерации главное действие — «Остановить». После остановки/ошибки доступно «Повторить ответ»: уже сохранённая реплика пользователя не дублируется, набранный новый черновик не стирается. Отмена перегенерации сохраняет старый ответ. Запоздавшие результаты отменённого запроса не сохраняются и не озвучиваются; фоновое обновление памяти также проверяет принадлежность текущему запросу. Повтор — временное UI-состояние, сбрасывается при смене режима/персонажа, редактировании и очистке истории; автоматической повторной отправки в облако нет. Таймаут показывает понятную ошибку, у Groq по-прежнему пробует локальный резерв.

Речь появляется постепенно через SSE (`stream: true`) в существующем `/v1/chat/completions` клиенте, включая Groq и Ollama. `chatStream.ts` отвечает только за чтение потока: дроблёные UTF-8/SSE frames, отделение reasoning, удержание незаконченных тегов/служебных блоков, отмена reader и проверка завершения. Поток без finish marker не считается готовым ответом. Preview обновляется не чаще раза в 50 мс (плюс финальный flush), проходит существующий speech guard и живёт только в состоянии страницы. Это предварительный текст: финальная валидация может его заменить. В память/историю, предложения действий и TTS попадает только полный проверенный результат. При retry, сбое и Groq → Ollama старый preview очищается; остановка удаляет незавершённый пузырь. Служебные роли не стримятся; обычный JSON-ответ сервера остаётся совместимым. Проверки — `chatStream.test.ts`.

Протокол сверён с [Groq Text Generation](https://console.groq.com/docs/text-chat) и [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility). UI-проверка потока выполнена в тестовом браузере 1920×1080 с локальным SSE-сервером, без ключа Groq; реальный провайдер и Electron требуют пользовательского smoke-check.

Граница облачного контекста — `src/lib/soul/cloudConversation.ts`: короткий фиксированный характер + до 10 сообщений (6500 символов истории) только из текущего явно открытого облачного разговора + новая реплика. Soul-дневник, Bible, приватные сообщения, think и события сессий не отправляются. При каждом переходе из приватного режима создаётся новый `groqConversationId`; только успешно обработанная облаком пара получает optional `cloudContextId` в существующей истории Soul. Старые сообщения без метки остаются локальными, редактирование снимает метку, перегенерация приватной реплики не отправляет её в облако. Ответ локального резерва также не становится облачной историей. Фактический облачный промпт доступен в диагностике хода. UI домена — `GroqSettings.tsx` / `groqSettings.css`.

Чат визуально строится как компактный профиль госпожи рядом с единой поверхностью переписки: портрет не превращается в полноширинный баннер, пустое состояние даёт три безопасных стартовых фразы, системные предложения остаются в доке над composer, а главное действие «Отправить» заметнее служебных кнопок. Page-level оформление принадлежит `src/pages/chatPage.css`; не наращивать этим доменом legacy-монолит `styles.css`.

Защитный контракт речи: ответ зеркалит язык последней реплики, а чужой алфавит, повторённый блок и упоминание затронутой жёсткой границы отправляют речь на один retry и затем в безопасный fallback. Явный opt-out не запускает роль «Разбор» и не может создать карточку. При программной сборке сессии вариант «Список» исключается до рулетки, если текущий сохранённый список отсутствует или пуст.

Не возвращать в сайдбар отдельные пункты «Дневник», «Статистика», «Достижения», «Избранное», «Додзинси», «Аномалия», «Ember Editor».

## Хабы

Лист `NavId` не схлопывается: вкладка = тот же id, что раньше был пунктом меню. `App.tsx` по-прежнему монтирует страницу по `nav`.

На развороте дневника — удалить запись, сверху — очистить всю книгу.

Код: `src/lib/hubNav.ts`, `src/components/HubChrome.tsx` (`ProgressHubChrome`), `src/components/hubChrome.css`.

### Контент

Кикер в шапке переключает **nhentai / gelbooru / censored / blacked / realbooru / xbooru / hypnohub / joidb**: клик по имени крутит по кругу, кнопка-шеврон открывает список всех. Вкладки общие: Новинки, Рекомендации, Поиск, Избранное, Списки. Состояние: `src/lib/contentHub.ts` (`joi-content-hub-v1`).

Сайдбар подсвечен при `doujin` и при старом `favorites` (глубокая ссылка на полку Gelbooru). Клик по пункту всегда ведёт в `doujin`.

Ветки: [DOUJIN.md](DOUJIN.md) (nhentai, ридер, прогон). Booru-источники (Gelbooru dapi, Gelbooru 0.1.11 `*.booru.org`, **realbooru** — Gelbooru 0.2 HTML без API, плюс **xbooru** / **hypnohub** — тот же dapi JSON, без API-ключа) — та же оболочка `GelbooruHub`: masonry-стена постов и локальная полка `mediaFavorites` кормит сессию и магазин. Realbooru `pid` — смещение постов (~29 на HTML-страницу), не индекс dapi; первая отрисовка не добирает вторую страницу до 36. Превью стены: `samples/{aa}/{bb}/sample_{hash}.jpg` у фото (оригинал `.jpeg`), у webm — постер `images/{aa}/{bb}/{hash}.jpg`, не сам ролик. Списки и прогон разделены по сайту (`joi-gelbooru-lists-v1` / `joi-booru-lists-{site}-v1`). Несохранённое видео в плеере идёт через `/api/media-proxy` с параллельными Range; сохранённое играет локальным blob. Превью в Electron — с CDN.

**joidb** (the-joi-database.com) — отдельный хаб, не Gelbooru: сетка HLS-роликов `auto-fill` 16:9 заполняет ширину хаба без горизонтального скролла. Вертикальный скролл — у `.joidb-hub` (как у Gelbooru), не у `.page--doujin`; следующие страницы подгружаются, когда sentinel внизу сетки входит в эту панель. Клик по карточке открывает страницу ролика: кино 16:9 слева с тёплым ambient-фоном, название и закладка/сердце в карточке под кадром, теги и описание — колонка справа; низ заполняет лента соседних роликов из текущей сетки. Сердце качает постер через `/api/media-proxy` и общую очередь избранного (тост как у Gelbooru), id `joidb-{hex}`. «Смотреть» включает HLS. Полный экран — контейнер кадра (кнопка справа сверху), не нативный fullscreen `<video>`, чтобы кнопки прогона слева оставались на экране. HUD прогона только пока прогон живой и ролик из его очереди: выход сохраняет паузу для «Продолжить», но не рисует счётчики на новинках. Пикер списков — тот же `doujin-picker`, что у nhentai/Gelbooru. Вкладка «Списки» — та же оболочка `doujin-lists` (создание плиткой, колода превью, очередь с перестановкой, док прогона); колода 16:9 с горизонтальным веером, не портретная как у манги. Сердце и закладка на превью и на странице. Прогон по VTT-куесам из списков стартует плеер сразу. Каталог с HTML `/videos` (pager load-more) и JSON `/api/video_popular/daily` через IPv4-прокси `/api/joidb` (хост `www.the-joi-database.com`). Стрим `GET /api/stream/{hex}`, превью-VTT `GET /api/vtt/{hex}`. Списки `joi-joidb-lists-v1`, избранное `joidb-{hex}` в `mediaFavorites`. Кикер: колонка имени под `realbooru` без лишнего зазора, стрелки и шеврон не ездят.

### Мини-игры

Кикер «Угольки», заголовок «Мини-игры». Вкладки:

| Вкладка | NavId |
| --- | --- |
| Игры | `minigames` |
| Аномалия | `ember` |
| Ember Editor | `ember_editor` |

Повторный клик по «Мини-игры» открывает последнюю вкладку (`joi-hub-play-v1`).

На каталоге игр шапка обычная; в Аномалии и редакторе — `tight`, поверх своих тулбаров. Пока запущена конкретная мини-игра (пазл, раннер, …), шапка хаба скрыта — выход в каталог возвращает вкладки. У строки «смотрит, как ты играешь» — портрет активной Госпожи из пака; карточки игр остаются с эмодзи. **Пошлая ферма** — один двор с сейвом (грядки, скот, станки, грузовик), не стадии: контракт [NAUGHTY_FARM.md](NAUGHTY_FARM.md).

Вкладки **Аномалия** (`ember`) и **Ember Editor** (`ember_editor`) — локальный замороженный эксперимент, не продуктовый трек. Не развивать, не звать дорожной картой. Отдельные пункты сайдбара под них не возвращать.

## First-visit briefing

Подсказки разделов (`src/lib/sectionBriefings.ts`) завязаны на хаб, не на каждую вкладку:

- любая вкладка Прогресса → briefing `diary`;
- `favorites` → briefing `doujin`;
- вкладки Аномалия / Ember Editor и каталог мини-игр — без overlay.

`briefingNavFor(nav)` — единственная точка маппинга. Не добавлять отдельные тексты для `stats` / `achievements`.

## Как менять

1. Новый **экран сессии / магазина / настроек** — новый пункт сайдбара, только если это не вкладка существующего хаба.
2. Новая **вкладка хаба** — id в `hubNav.ts` (или `contentHub.ts`), chrome, `App.tsx`, тесты, эта страница.
3. Не копировать пилюли вкладок в `styles.css`: Прогресс/Мини-игры — `hubChrome.css`; Контент — `doujin.css`.
4. Не вводить `NavId` `"progress"` / `"play"` / `"content"`: сайдбар резолвит хаб в существующий лист id.
