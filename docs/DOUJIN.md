# Додзинси (nhentai API v2)

Хаб живёт в разделе **Контент** (один пункт сайдбара; карта оболочки — [HUB.md](HUB.md)). В шапке кикер переключает **nhentai / Gelbooru**; вкладки общие. Этот документ — ветка nhentai (сетка томов, ридер, избранное аккаунта, списки и прогон). Gelbooru — та же оболочка: masonry-стена постов и локальная полка (`mediaFavorites`); в колоду сессии идёт только она, не тома nhentai. Списки Gelbooru читаются в lightbox и могут идти **прогоном** (тот же `ReadingRunState`, `source: "gelbooru"`). На Рекомендациях карточка «Связка вкуса» (теги + тип + Обновить) — нижнее окно поверх стены, как поиск. «Обновить» крутит пул AND-связок: персонаж/лор/артист × фетиш/действие/одежда/тело, иногда тройка или один якорь; порядок шаффлится каждый полный круг, как у nhentai, а не соседние теги из топа полки. Несколько сердечек подряд в обеих библиотеках идут очередью; справа внизу — «Успешно сохранено».

## API

- База: `https://nhentai.net/api/v2/` (прокси `/api/nhentai` в Vite).
- Заголовок `Authorization: Key <ключ>` — ключ только в `localStorage` `joi-doujin-settings-v1`, не в git.
- User-Agent: `JOI-Conductor/0.1 (local desktop)`.
- Картинки: `/api/media-proxy` с Referer `https://nhentai.net/` для `*.nhentai.net`.
- Лимит клиента: не больше 8 запросов / 60 с и минимум 3.5 с между ними (без пачки в 15). 429 и шлюз Cloudflare 502/503/504 — пауза по Retry-After и повтор (до 6 попыток), в UI короткая фраза без JSON. Прерванный проход каталога продолжает с `lastPage + 1`, не с первой страницы.
- `GET /search` `sort`: `date` | `popular` | `popular-today` | `popular-week` | `popular-month` (не `newest`).
- Поиск: строка фильтров (категория / страницы / популярность / язык / сорт) живёт в сворачиваемом окне поверх сетки внизу экрана (то же у Gelbooru), чтобы шапка вкладок не прыгала. У nhentai фильтры сидят в одном поле с запросом, как теги у Gelbooru; префиксы сайта — за «?» (`tag:`, `artist:`, `parody:`, `language:`, `category:`, `pages:`, `favorites:`, `uploaded:`, `title:`, `jtitle:`). Автозаполнение в поле — имена из синхронизированных тегов избранного (последний токен, с учётом префикса типа). Один фильтр как страница сайта (`artist:muk`, `artist:mokuyama-hito`, `https://nhentai.net/artist/muk/`) идёт в `GET /tags/{type}/{slug}` → `GET /galleries/tagged?tag_id=` — та же лента, что `/artist/muk/`, не префикс `/search`. Слаги с дефисом переводятся в имя с пробелом. Целиком в поле можно вставить код галереи (`675882`, `#675882`, `g/675882`, `id:675882`) или ссылку `https://nhentai.net/g/675882` — тогда идёт `GET /galleries/{id}`. Смешанный запрос (`artist:muk tag:glasses`) остаётся текстовым `/search`.
- Сетка обложек подгоняется под окно (`fitDoujinGrid`): крупные карточки, `pageSize = cols × rows`. Новинки и поиск — до 5 колонок. Избранное держит колонку тегов слева и режет сетку до 4 колонок (типично 4×2 = 8 карточек вместо 5×2 = 10). `GET /favorites` без `per_page` режется в то же окно. Лента часто отдаёт только `tag_ids`: бейджи JP/EN/ZH берутся из известных language-id (6346 / 12227 / 29963). Если у работы несколько разговорных языков — все бейджи на карточке.
- `GET /favorites` — список избранного аккаунта. Сердечко в приложении = это избранное: `POST` / `DELETE /galleries/{id}/favorite`. Прокси Vite пробрасывает GET/POST/DELETE.

- `GET /favorites` — список избранного аккаунта. Сердечко в приложении = это избранное: `POST` / `DELETE /galleries/{id}/favorite`. Прокси Vite пробрасывает GET/POST/DELETE.
- У nhentai нет своего CF-движка рекомендаций: только `GET /galleries/{id}/related` и `/search` / `/galleries/tagged`. Хаб крутит AND-связки вкуса (несколько parody/character/artist × разные mood-теги, любимый тег, …) кнопкой «Обновить»: пул до 24 пар, порядок шаффлится каждый полный круг, чтобы не зацикливать одни и те же два тега. «Похожие» — одна работа-сид на первой странице окна. Если связка одна, «Обновить» по-прежнему сдвигает окно поиска на 3 страницы. Звезда у тега в Избранном даёт ему больший вес.
- Недочитанное из очереди — кнопка «Продолжить» под «Читать» на карточке списка (курсор очереди и страница из IndexedDB). Пока ничего не начато, кнопки нет. «Читать» открывает первую работу с нуля.
- Ридер префетчит ±3 соседние страницы текущей галереи через media-proxy, не следующую работу плейлиста и не extra `GET /galleries`.

## Фильтр тегов

Один blacklist. Режет query (`-tag`) и карточки/деталку по именам тегов.

- **Живой слот:** всегда дефолт (`lolicon`, `shotacon`, `loli`, `shota`, `cub`, `child`, `underage`, `toddlercon`). Редактора нет.
- **Песочница:** Настройки → Медиа → «Blacklist (песочница)» — весь список, не добавка сверху. Хранение `joi-doujin-blacklist-sandbox-v1`. Кнопка сброса к дефолту.

Код: `src/lib/doujin/safety.ts` (`effectiveBlacklist`).

## Избранное аккаунта

Сердечко на карточке и кнопка в ридере синхронизируются с избранным nhentai (тот же ключ API, что в Настройках). Несколько сердечек подряд ставятся в очередь (по одному запросу, из‑за лимита API) и не теряются; справа внизу то же всплывающее окно, что у синхронизации каталога: «Сохранение N / M», затем «Успешно сохранено». Вкладка «Избранное» читает локальный каталог после «Синхронизация вкусов» (обложка, название, страницы, tag ids в IndexedDB `tasteGalleries`); `GET /favorites` при листании не дергается. Клик по работе — `GET /galleries/{id}` и при необходимости дописывает карточку в каталог. Слева — колонка всех именованных тегов избранного (пародии, персонажи, авторы, круги, теги, …): поиск над «Любимые» фильтрует список и подсказывает имена; разделы сворачиваются. Клик по имени тега фильтрует локальный каталог (тег поднимается в «Сортировка» над «Любимые»; повторный клик снимает; несколько тегов, ↑↓ меняют приоритет). Сетка и пагинатор показывают только совпадения (`12 работ · 2 стр.`), не все 500 страниц избранного. Над сеткой шапка хаба всегда одна: кикер источника и вкладки. Закладка «в список из найденного», барабан «Порядок» (только Избранное) и пагинация «Назад / N / Дальше» живут в фиксированном окне поверх сетки внизу экрана на Новинках, Рекомендациях, Поиске и Избранном. Порядок как в рулетке: в избранное (позиция в ленте сердечек, 0 = самое новое; если у старого каталога нет `ord`, один проход «Обновить каталог» проставляет порядок даже на страницах с обложками, без паузы 8 с), дата выхода, популярность, страницы — теги только режут список, барабан его сортирует. Клик по `1 / N` открывает барабан страниц. Кнопка ⌕ справа ищет тег на сайте. Звезда помечает любимый.

Локальный IndexedDB `joi-conductor-doujin` — каталог избранного (`tasteGalleries`: карточка + tag ids), кэш обложек и прогресс страницы. Рекомендации — теги избранного аккаунта (`tag_ids` → `GET /tags/ids`). Быстрый старт — выборка (~2 страницы, кэш сессии `joi-doujin-account-taste-v2`, до 100 имён за один `/tags/ids`). Полная картина — кнопка «Синхронизировать каталог» над «Любимые»: постепенно обходит `GET /favorites` (~25 работ на страницу, пауза ~8 с; `per_page` список игнорирует), пишет превью/данные каждой работы и резолвит имена всех тегов реестра. Прогресс — полоска в колонке тегов и всплывающее уведомление (страница N из M, затем имена тегов, «каталог готов»). Повторный запуск с дырами в превью идёт с первой страницы и дописывает карточки (страницы, где обложки уже есть, пролетает без паузы 8 с). Мгновенный «каталог готов» только если у всех работ уже есть превью и на первой странице нет новых сердечек. `count` — сколько работ реестра содержат тег, не site-wide `gallery_count`. В рейку попадают все именованные id; звёздный тег без имени в кэше всё равно получает счётчик из реестра по id. Если избранное пустое — подсказка поставить сердечки.

Карточка в ленте открывает **страницу описания** (обложка, теги-пилюли, страницы, похожее), как карточка галереи на nhentai. «Читать» и превью страниц входят в ридер. Клик по тегу — поиск с префиксом сайта. На обложке: бейдж языка (JP/EN/ZH) и закладка в локальный список чтения рядом с сердечком.

## Списки чтения

Локальные очереди в `localStorage` `joi-doujin-reading-lists-v1`, не избранное nhentai. Вкладка «Списки» доступна без API-ключа. Обзор очередей — сетка из 4 колонок: стопка уникальных обложек (не добирать слои превью той же работы; цикл до 8 обложек в 4 анимированных слотах, на наведении веер из 4). Первые две карточки ряда: автоочередь (портрет и имя активной госпожи на «обложке», барабан 10/15/20 внизу, кнопка «Выбор {имя}» в строке с названием; подсказка «любимые и редкие · EN» в значке i) и «+» / Создать (`origin: user`). Автоочередь — `origin: mistress`, страницы в IndexedDB `pageBlobs`. Дальше пользовательские очереди. На карточке «Читать» всегда с первой работы, «Продолжить» под ним — с курсора и недочитанной страницы, **Скачать** — все страницы очереди в `pageBlobs` (нужен API-ключ). Клик по карточке открывает очередь. Шапка: крупное имя без рамки, карандаш слева включает правку (не клик по названию), справа число работ и «своя очередь» / «её очередь»; кнопка **Описание** открывает заметку списка (`note`, до 4000 символов). «Читать» и **Начать прогон** — в нижней панели, без таймера у «Читать»; там же **Скачать**. Внутри: слева очередь, справа превью. Выше/Ниже у номера и крестик «Убрать» — при наведении; убрать дропает кэш страниц, если работы больше нет ни в одном списке. Снимок тегов и превью страниц пишется в ту же очередь. Не путать с IndexedDB избранного (сердечко). Очистка: удалить очередь или ключ `joi-doujin-reading-lists-v1`.

Закладка на карточке открывает выбор списка: клик по очереди сразу добавляет или убирает. Закладка в нижнем окне пакует N работ из текущей ленты (барабан «Сколько», имя нового списка или существующая очередь) — как «из найденного» у Gelbooru; карточка по-прежнему только одна работа. Новый список — свёрнутая строка внизу, не оранжевое «Создать» на весь диалог. Ридер из очереди листает как плейлист.

Ридер: шапка из иконок (назад, масштаб −/+, убрать интерфейс, избранное), номер страницы. Снизу полоска прогресса с превью страницы при наведении и кликом-переходом; по бокам иконки листания. Клик по центру или кнопка «убрать интерфейс» прячет панели (Esc возвращает). Стрелки, пробел, +/− и Ctrl+колёсико. В режиме списка на краю тома — иконка пропуска работы; «К списку» возвращает в очередь, не на страницу описания. Страницы вокруг текущей (±3) подгружаются заранее. Если страница уже в кэше прогона (`pageBlobs`), ридер берёт blob, иначе media-proxy.

## Прогон чтения

Не сессия: нет метронома, нет `sessionRuntime`. **Начать прогон** сразу включает таймер, если раньше не останавливались. Если есть место остановки или сохранённый прогон — окно в стиле списка: **Сначала** / **Продолжить**. **Читать** / **С начала** по-прежнему просто открывают ридер/lightbox без таймера. Выход из ридера прогона спрашивает подтверждение только если уже есть прогресс; иначе прогон сбрасывается без окна.

Один живой прогон на хаб: `localStorage` `joi-doujin-reading-run-v1`. Поле `source: "nhentai" | "gelbooru"` (старые записи без поля — nhentai). Переключение кикера не затирает чужой source.

- **Госпожа** (`origin: "mistress"`): она собирает 10/15/20 работ с вкладки Списки («Выбор {имя}») — AND-пары как рекомендации, всегда `language:english`, без кругов и языков как вкуса. Страницы очереди качаются в IndexedDB `pageBlobs`. Задания на части страниц (не обложка/оглавление/хвост). Кнопки как в сессии, без BPM: пауза, эдж, руина, кончил без разрешения, **Разрешение** (`rollFinale` + камплей). Пропуск задания роняет настроение и делает следующие тяжелее.
- **Самоотчёт** (свои списки): те же E/R/C и пауза, без Разрешения. C — честный отчёт и камплей. В конце полку не докидываем: выбрать другой свой список, либо собрать автоочередь, либо «составлю сам».
- Обложки: `contentPageRange` — у коротких томов только первая страница, иначе 2–3 спереди и 1–2 сзади, не больше 30% тома. Задания не стартуют на первой и последней странице.
- Финал её очереди без оргазма — опрос и докидка **того же** mistress-списка (любимые или редкие теги). Пользовательские коллекции не трогаем.
- Дневник: `source: "reading"`, в статистике корзина «Чтение». Настроение — глобальный `moodScore` госпожи (`saveControlMood` / `applyControlMoodDelta`).

### Gelbooru списки

Та же вкладка «Списки», локальные очереди `joi-gelbooru-lists-v1`. Карточка: **Читать** открывает lightbox с первого поста, **Продолжить** — с курсора; клик по колоде — деталка. В панели: **С начала** / **Продолжить** / **Скачать** / **На полку** / **В сессию** (колода JOI, как раньше) / **Начать прогон**.

Прогон не сессия: очередь — **один том**, пост — страница (`galleryId` = id списка, `pageIndex` = курсор). HUD, пауза, E/R/C, разрешение госпожи, опрос и self-end — те же компоненты, что у nhentai. **В сессию** метроном не включает.
